# DB setup plan (2026-11-12)

Goal: get the DuckDB lab database (`db_` domain) merged and usable. One task per
session: do the next unchecked step, tick it, commit, stop.

## Decisions (already made -- don't re-ask)

- Single computer, single user.
- Live DB: `~/lab-db/lab.duckdb` -- local only, never on OneDrive (sync breaks
  DuckDB's file lock / `.wal`).
- OneDrive `Forschung/LabDB/`:
  - `raw/<experiment_code>/{facs,elisa,histo,meta}/` -- raw exports, source of truth
  - `snapshots/YYYY-MM-DD/` -- `EXPORT DATABASE` after each import session
- Backup = a two-line snippet in the import script, no `db_backup()` function
  (yet).
- Schema: `docs/superpowers/specs/2026-07-17-facs-db-schema-design.md` (only on
  master as draft -- read only if a step needs it).
- **Update 2026-11-12 (FACS pipeline Stage 0):** this plan is now Stage 0 of
  `2026-11-12-facs-pipeline-workflow-design.md`. The `db-domain-functions`
  worktree no longer exists; `origin/worktree-db-domain-functions` (`3c5308a`)
  was merged into `worktree-facs-pipeline-workflow` (`2f12c2c`). All remaining
  steps happen on that branch; everything goes to master together at step 5.
- Old SQLite scripts (`R/DB-setup.R`, `R/export-to-sql.R`) are no longer in
  `R/` -- nothing to move.
- Don't read the old plan `2026-07-17-db-domain-functions.md` (1,700 lines) unless
